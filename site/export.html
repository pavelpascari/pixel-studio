Bundles and game engines

The CLI turns a spec into a bundle for the web (one JSON file, every size, all the metadata) or into a sprite sheet with Aseprite-format JSON that PixiJS and Phaser load directly.

From spec to files

    node bin/pixel.mjs validate goose.json                       // errors with JSON paths, clipped parts, missed feet
    node bin/pixel.mjs preview  goose.json --anim walk,jump      // contact sheet PNG of those animations
    node bin/pixel.mjs bundle   goose.json --out site/goose.bundle.json
    node bin/pixel.mjs export   goose.json --res 32 --out game/  // game/goose.32.png + game/goose.32.json

What a bundle holds

Sheets are PNG data URLs, one per size. A skin is stored as a change to the plain sheet when that is smaller (recolor: colours swapped, overlay: pixels drawn on top), otherwise as its own sheet. Events, attachment points, the foot line, speeds and the state machine are stored in units, so one table serves every size. The full format is in docs/runtime.md.

PixiJS

pixel export writes frames named by index, a PixiJS animations map, and per-frame durations. This example loads PixiJS 8 from a CDN.

Phaser

Phaser reads the same JSON as an Aseprite file: every animation becomes a Phaser animation, with its frame durations.

    preload() {
      this.load.aseprite('goose', 'goose.32.png', 'goose.32.json');
    }
    create() {
      this.anims.createFromAseprite('goose');            // idle, waddle, run, honk, jump, …
      const goose = this.add.sprite(100, 100, 'goose').setScale(3);
      goose.play({ key: 'waddle', repeat: -1 });
    }

Attachment points travel as Aseprite slices (one key per frame), and the extras (events, speed, ground) under meta.pixelStudio.
