Pixel Studio makes small animated pixel characters and gives them a home on a website. You describe a character,
the engine draws it as pixel art at every size, and one HTML element plays it on your page. These six are running
in this post:

Each of them is one file, and the page you are reading plays them with one script.

## A character is a description

You don't paint a Pixel Studio character pixel by pixel. You write it down: a JSON spec of shapes on a skeleton,
the materials they are made of, and the animations it plays. The engine turns that into pixel art at 16, 32 and
64 px, with shading, texture, dithering and outlines suited to each size. The smallest keeps the silhouette; the
largest gets the fur.

Most of the motion comes with the skeleton. A spec can stand on a figure (a goose, a human, a dog, a chibi or a
blob) whose motion models make it walk, run, jump and climb. Feet stay planted, heads stay steady, tails follow
through, and nobody writes a keyframe.<MarginNote kind="field" numbered>The fox's gallop is measured from Muybridge's photographs of running hounds. All the motion data comes from public-domain and openly licensed sources, each one credited in the repository.</MarginNote>

So a new character can be a few lines. This is a whole new goose, a golden one called Marigold:

```json
{
  "extends": "./node_modules/@pixel-studio/core/examples/goose-base.json",
  "name": "Marigold",
  "materials": {
    "feather": { "color": "#e8b04a" },
    "beak": { "color": "#d94b32" }
  }
}
```

It gets every motion of the base goose, from idle and waddle to flap and fly. A character can also carry other
looks, called skins: root, the goose in the hoodie, has a party hat and a red-team colour scheme in the same file.

## Written so an agent can write it

The tagline says "agents describe characters", and it means it. A language model is good at writing a precise
description and poor at placing pixels, so Pixel Studio asks it for the description. The spec reference is written
as a brief for an agent. Mistakes come back with a JSON path and a did-you-mean, and `pixel ascii` prints a
character as text, for an agent that can't see images.

The studio puts this in a loop. Describe a character in a sentence. Claude writes the spec, the engine draws it in
every animation at every size, and Claude looks at the drawing and revises. Then you ask for changes in plain words
("make the antenna blink") and it goes round again. When it looks right, you export one bundle file.<MarginNote kind="field" numbered>When a spec Claude writes doesn't validate, the studio hands the errors back for a fix (up to twice) before it draws anything, so what you see is a character, not an error message.</MarginNote>

Creating with Claude uses your own Anthropic API key. It stays in your browser, and requests go straight to the
API. Without a key, the examples, the editor and the playground all work, and you can edit the JSON yourself.

## One tag on the page

```html
<script type="module" src="pixel-sprite.js"></script>

<pixel-sprite src="goose-root.bundle.json"
  size="128" skin="party"
  alt="root, a goose in a party hat"></pixel-sprite>
```

The behaviour comes with the bundle: this goose carries a small state machine, so the page needs no code for the
honk. The script is 14 KB over the wire, with no dependencies and no build step. The smaller example characters
are 9 to 43 KB each; a goose with front and back views and two skins is about 100 KB.

The element tries to stay out of the way. It stops drawing when it is off-screen, shows a still frame when the
reader asks for reduced motion, can be paused, and reads its `alt` to screen readers.

## Characters that live on the page

A sprite plays where you put it. `<pixel-stage>` lets characters move around your layout. Mark elements as surfaces
and the characters walk along their top edges, jump between them, sit on an edge, and hide behind anything marked as
a hiding spot. They never block a click.<MarginNote kind="field" label="The goose">I walk on your cards. I do not press your buttons. Mostly.</MarginNote>

They react to the reader too: tap one and it startles and runs off; scroll fast and it calls after you. And a page
can give them something to do. A scene is a short list of steps written as data and started by a click on any
element, with no animation code. On the [home page](/), a gosling picks up a letter, hurries off to post it,
and comes back.

## Where it stands

Pixel Studio is open source under the MIT licence, and it is an alpha. It comes as two npm packages, always
released together under one version:

- **`@pixel-studio/runtime`** plays characters: `<pixel-sprite>` and `<pixel-stage>`, all a website needs.
- **`@pixel-studio/core`** makes them: the engine, the `pixel` command, the figures, the example characters and the
  reference docs.

Until 1.0 the spec format may still change. Every change, and what to update when it does, goes in the
[changelog](/changelog/). The [guide](/docs/guide/) shows each feature running next to its code, and
[getting started](/docs/reference/getting-started/) goes from an empty folder to your own goose on a page in five
steps. The source, issues and discussions are on [GitHub](https://github.com/pavelpascari/pixel-studio).

<script>{`
  (() => {
    // One control for every character in the post (WCAG 2.2.2). Its name stays the same; aria-pressed says
    // whether they are paused.
    const button = document.querySelector('[data-ps-pause]');
    if (!button) return;
    button.addEventListener('click', () => {
      const paused = button.getAttribute('aria-pressed') !== 'true';
      button.setAttribute('aria-pressed', String(paused));
      for (const sprite of document.querySelectorAll('pixel-sprite')) sprite.toggleAttribute('paused', paused);
    });
  })();
`}</script>
